# Безопасность сайта

Сайт является статическим и не должен содержать пароли, API-ключи, токены,
закрытые документы или персональные данные клиентов.

## Перед публикацией на GitHub Pages

1. В `Settings → Pages` включить `Enforce HTTPS`.
2. Включить двухфакторную аутентификацию для владельца репозитория.
3. Защитить основную ветку: запретить force-push и удаление ветки.
4. Проверить историю Git на наличие `.env`, ключей, токенов и персональных данных.
5. Выдавать доступ к репозиторию только тем, кому он действительно нужен.
6. Не добавлять сторонние скрипты и аналитику без проверки источника.

## При переносе на обычный хостинг

Настроить HTTP-заголовки на сервере:

- `Content-Security-Policy` — перенести политику из `index.html` в HTTP-заголовок;
- `Strict-Transport-Security: max-age=31536000; includeSubDomains`;
- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`;
- `Cross-Origin-Opener-Policy: same-origin`;
- `Content-Security-Policy: frame-ancestors 'none'` для защиты от clickjacking.

Формы сейчас не сохраняют данные на сервере: после проверки полей они открывают
WhatsApp с подготовленным сообщением. При появлении backend/API обязательны
серверная валидация, ограничение частоты запросов, журналирование и защита от спама.
